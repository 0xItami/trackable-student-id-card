01System overview & chosen approach

The demo requirement — live position on a map and operation beyond 200 m from a portable badge — rules out plain passive RFID (a few centimetres) and classic Bluetooth (tens of metres). The build is a single all-in-one board: a LilyGO T-A7670E, which carries the ESP32, a 4G LTE modem (with built-in GNSS), the SIM slot, and battery charging on one PCB. The card reads its own GPS and sends the position over LTE straight to the backend. There is no base station, no radio pair to match, and — because the cellular network carries the data — range stops being a design problem. 200 m is trivially within reach. Consolidating everything onto one board also removed the separate modem, GPS, charger, and capacitor from the earlier plan.

Why one integrated board? The LilyGO T-A7670 puts the MCU, LTE modem, SIM slot, GPS and charger on a single PCB. That deletes almost all wiring and every gotcha of a discrete build (modem power bursts, the decoupling capacitor, level shifting). Physical assembly is: insert SIM, plug in battery, screw on two antennas, flash. Lowest-risk path for the build.
Will 4G LTE work in Zaria? Yes — the A7670E supports band B3 (1800 MHz), the main Nigerian 4G band used by MTN, Airtel and 9mobile. Use a 4G-enabled SIM and sanity-check it browses on a phone at the demo spot. (Urban Zaria has solid LTE coverage.)
One thing to verify on the board: GNSS + the GPS antenna port exist only on the A7670E-with-GPS variant. Confirm your board has a second antenna connector labelled GPS and shipped with two antennas — that is the position source for the whole project.
On physical size: a true ISO card is about 85.6 × 54 × 0.76 mm. The development board alone is about 106 mm long, so the current enclosure calculates to roughly 110.4 × 75.1 × 8.4 mm before printer tolerances. It is a lanyard/pocket badge, not a wallet card. A custom PCB is the correct route to ISO dimensions.

04Day-by-day schedule

JUL 25 · TODAY software + hardware working

Already achieved: board flashed; A7670E modem identified; SIM registered on MTN (621‑30); LTE data connected; built-in GNSS powered and answering; card POSTing live to the backend over 4G (HTTP 200); ABU-branded dashboard with live map, roster, search, ping, activity log and Swagger API docs; indoor cell-tower fallback verified; GPS-hold logic added.

JUL 26–27 milestone: first real satellite fix

The one untested thing. Power the card from a USB power bank, take it outside with the GPS antenna facing up, and wait 1–5 min for the cold start. Confirm +CGNSSINFO fills in and your true position appears on the map. Screen-record it — that recording is your insurance for the rest of the project.

JUL 28 200 m range + indoor hold

Walk the card 200 m+ away from the laptop and log distance vs. successful updates and CSQ — the expected result is that distance does not degrade performance, because the path is the cellular network. Then walk back indoors and confirm the dashboard holds the last GPS position (labelled “Last GPS fix”) instead of jumping to a coarse cell position.

JUL 29–30 optional: indoor accuracy

With time in hand, add WiFi-based indoor positioning: the card scans nearby access points and the backend resolves them to a position via a geolocation API (keeps TLS off the modem). Gets indoor accuracy from ~km down to tens of metres. Skip if sourcing an API key stalls — GPS-hold already covers the demo.

AUG 28

Freeze functionality, flash the authenticated firmware, verify the real card posts, and measure the board, battery and antennas before committing to a full enclosure print.

AUG 29 live demo

Record measured results: first-fix time, satellite count/fix quality, 200 m continuity, update latency and battery runtime. Save screenshots, serial logs and one clean route for playback.

AUG 30 rehearsal

Full timed dry run of the exact sequence the panel will see (see the demo runbook in TECHNICAL_DOCUMENTATION.md §12). Charge the battery, reserve/confirm the ngrok domain, pack the kit, print the report.

AUG 31 presentation

Presentation day: use the live card first, then route playback or simulator only as a declared fallback.
